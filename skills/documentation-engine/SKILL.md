# Documentation Engine

Documentation must describe the repository as it exists, not an idealized design. Link claims to files/types/settings and version-sensitive official docs. Preserve hand-written rationale. Update only sections affected by verified changes.

Useful outputs include system maps, assembly responsibilities, scene flow, multiplayer authority model, save format/migrations, input architecture, build/release runbooks and troubleshooting playbooks.
